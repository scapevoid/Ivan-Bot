## Обзор проекта

Бот предназначен для сбора анкет от потенциальных клиентов строительной компании IVAN DOM Rostov. Пользователь проходит последовательность вопросов — от целей строительства до деталей участка — и в конце его ответы сохраняются в текстовый файл, который администратор может скачать.

Анкета содержит **~88 вопросов**, разбитых на тематические зоны:
- цели и ценности строительства
- категория и площадь дома
- архитектурный стиль и фасады
- планировка (прихожая, кухня, спальни, санузлы, кабинет, хозблок и т.д.)
- параметры участка
- сроки и приоритеты

---

## Почему telebot

Библиотека [`pyTelegramBotAPI` (telebot)](https://github.com/eternnoir/pyTelegramBotAPI) была выбрана осознанно — как самый простой и понятный инструмент для работы с Telegram Bot API на Python.

**Ключевая причина** — бот изначально получался очень нагруженным: большое количество шагов, ветвлений, кнопок и медиафайлов. В таких условиях важно было, чтобы сам фреймворк не добавлял сложности. `telebot` даёт простой декораторный синтаксис для хэндлеров, понятную работу с `InlineKeyboardMarkup` и не требует сложной настройки.

Альтернативы вроде `aiogram` (асинхронный) добавили бы накладные расходы на понимание async/await, что при командной работе и частых правках было бы лишней сложностью.

## Архитектура: блочная система

### Откуда появились блоки

По техническому заданию контент бота (тексты вопросов, картинки, кнопки) нужно было **менять часто**. В первоначальной модульной версии каждое изменение требовало правки в нескольких местах кода, что было неудобно и приводило к ошибкам.

Было принято решение вынести каждый вопрос (или смысловой шаг) в отдельный **блок** — изолированный файл, который легко найти, прочитать и исправить. Такой подход позволяет:

- редактировать текст, фото или кнопки одного вопроса, не затрагивая остальные
- копировать блок как шаблон при добавлении нового вопроса (copy-paste архитектура)
- передавать отдельные блоки другому разработчику без риска сломать всё остальное

### Два типа блоков

```
blocks/              # Вопросные блоки — шаги анкеты
information_blocks/  # Информационные блоки — справочный контент (подробнее о стилях, материалах и т.д.)
```

Каждый блок — это Python-модуль с функцией-хэндлером вида `block4_XX(message, bot)`. `main.py` импортирует все блоки и вызывает нужный в ответ на callback или сообщение пользователя.

### Кэширование сообщений

Ряд блоков использует `cache` — словарь `{chat_id: [messages]}` — чтобы потом удалить отправленные ботом сообщения при переходе к следующему шагу. Это делает интерфейс чище.

```python
from blocks.block74.handler74 import cache as cache74
# ...
messages = cache74.get(call.message.chat.id, [])
for msg in messages:
    bot.delete_message(call.message.chat.id, msg.message_id)
```

## История рефакторингов

### Рефакторинг №1 — переход на блоки

Первые ~10 вопросов были написаны как обычные модули прямо внутри основного кода. По мере роста анкеты стало очевидно, что такой подход не масштабируется: менять тексты и кнопки было неудобно, код становился монолитным.

**Решение:** вынести каждый вопрос в отдельный файл-блок. Блок содержит всё необходимое для одного шага — текст, медиа, клавиатуру, логику перехода. `main.py` превращается в «маршрутизатор», который только вызывает нужный блок.

### Рефакторинг №2 — унификация блоков как copy-paste шаблонов

После первого рефакторинга первые блоки ещё отличались по структуре от новых. Был выполнен второй проход, чтобы привести все блоки к единому виду — чтобы любой блок можно было скопировать как шаблон и подставить новые данные (текст, номер поля в БД, callback-имена) с минимальными правками.

## Мультивыбор: решение проблемы

Несколько вопросов анкеты допускают **выбор нескольких вариантов** одновременно (например, материалы фасада, наполнение санузла, объекты на участке).

Реализовать это в Telegram было нетривиально: стандартные кнопки не имеют встроенного состояния "выбрано/не выбрано".

**Решение, найденное спустя ~неделю работы:** состояние выбора передаётся прямо в `callback_data` кнопки. Выбранные варианты хранятся как строка через запятую и обновляются при каждом нажатии. Кнопка перерисовывается с галочкой ✅ у выбранных пунктов.

```python
# Пример из main.py
new_status = status.split(",") if status else []
if number in new_status:
    new_status.remove(number)
else:
    new_status.append(number)
updated_status = ",".join(new_status)

prefix = "✅" if str(i) in new_status else ""
btn = InlineKeyboardButton(
    f"{prefix} {text}",
    callback_data=f"variant_data_{i}_{updated_status}_{handler}"
)
```

Кнопка «Продолжить» передаёт итоговую строку выбора в следующий обработчик.

### Нумерация блоков

Номер блока соответствует номеру поля в базе данных (индексу в строке ответов). Суффиксы (`_1`, `_2`, `_3`, `_5`) обозначают подветки или альтернативные шаги внутри одной темы (например, `block38`, `block38_2`, `block38_3` — разные пути в зависимости от предыдущего ответа).

## Основные компоненты `main.py`

### Инициализация

```python
token = gettokenbot.get_token()
path = getpath.pathreturn()
bot = TeleBot(token)
admin_ids = ["902026475", "635863841", ...]  # ID администраторов
```

### Команда `/start`

Создаёт запись пользователя в БД, отправляет приветственное фото с тремя кнопками:
- **Начать заполнение** — запускает анкету
- **Зачем это всё** — информационный блок о ценности анкеты
- **Видео про проектирование** — ссылка на видео

### Единый callback-обработчик

Все нажатия на кнопки обрабатываются в одном большом обработчике `callback_start`. Логика построена на цепочке `if call.data == "..."` проверок, каждая из которых либо сохраняет ответ и вызывает следующий блок, либо показывает информационное сообщение.

```python
@bot.callback_query_handler(func=lambda call: True)
def callback_start(call: CallbackQuery):
    if call.data == "start_filling":
        handler1.block4_1(call.message, bot)
    if call.data == "onefloor":
        createdb.exdb("Рассматриваю одноэтажные проекты", 13, call.message.chat.id)
        handler12_1.block4_12_1(call.message, bot)
    # ...
```

### Отладочные команды (skip)

```python
@bot.message_handler(commands=['skip'])
def asdasd(message):
    handler73_5.block4_40_1(message, bot)   # Перейти к блоку 73_5

@bot.message_handler(commands=['skip2'])
def asdasd(message):
    handler311.block4_31(message, bot)       # Перейти к блоку 30_5
```

Используются при разработке для быстрого перехода к нужному шагу без прохождения всей анкеты.

## База данных и хранение ответов

Каждый пользователь хранится как файл `{chat_id}_id` в директории `path`. Ответы записываются в одну строку через разделитель `, `. Значение `NULL` означает, что вопрос был пропущен.

```python
# createdb.exdb(answer, field_index, chat_id)
createdb.exdb("Рассматриваю одноэтажные проекты", 13, call.message.chat.id)
```

При завершении анкеты вызывается `write_to_excel(message)`, которая читает строку из файла, расставляет ответы по полям и сохраняет читаемый текстовый отчёт в `datausers/{chat_id}.txt`.

## Админ-панель

Доступна по команде `/admin` или `/adminpanel` только для пользователей из списка `admin_ids`.

| Кнопка | Действие |
|---|---|
| Мульти-Рассылка | Отправить сообщение всем пользователям в базе |
| Скачать все | Скачать архив `.zip` со всеми анкетами |
| Удалить все | Очистить все сохранённые анкеты |

### Мульти-рассылка

```python
def multi_send(text, message):
    for i in os.listdir(f"{path}"):
        ida = i.split("_")[0]   # извлекаем chat_id из имени файла
        bot.send_message(ida, f"{text.text}")
```


## Как добавить или изменить блок

### Изменить текст или кнопки существующего блока

1. Найти файл блока в `blocks/blockXX/handlerXX.py`
2. Поправить строку с текстом или список кнопок
3. Перезапустить бота — изменения вступят в силу

### Добавить новый вопрос

1. Скопировать любой существующий блок как шаблон
2. Переименовать файл и функцию (`blockXX`, `block4_XX`)
3. Прописать нужный текст, медиа и кнопки
4. Добавить импорт в начало `main.py`
5. В `callback_start` добавить `if call.data == "..."` с вызовом нового блока
6. Добавить новое поле в `write_to_excel` и обновить индексы в `createdb`

### Добавить мультивыбор

Использовать паттерн `variant_data_{номер}_{статус}_{handler}` как в существующих блоках (например, handler `141`, `171`, `191`). Логика уже реализована в `callback_start` — достаточно добавить новый `elif handler == str(НовыйНомер)` с нужными вариантами.
